AI Model & External Services Substitution: Wherever the documentation specifies OpenAI GPT-4o, GPT-4, OpenAI APIs, local Ollama models, qwen2.5-coder, Whisper STT, or ElevenLabs TTS, Antigravity must instead use the project's current production stack. All AI-powered features—including the Conversational Tutor, Intent Classification, Code Analyzer explanation generation, Quiz Generator, educational explanations, and any future AI modules—must use the Google Gemini API with **gemini-2.5-flash** via the **GEMINI_API_KEY** environment variable. No OpenAI or local LLMs are part of this build. Embeddings for the RAG pipeline (ChromaDB) must use **gemini-embedding-001** consistently for all vector generation. Speech-to-Text must use the browser's native **Web Speech API (SpeechRecognition)**, and Text-to-Speech must use the browser's native **Web Speech API (SpeechSynthesis)**. Do not introduce Whisper, ElevenLabs, Azure Speech, or any other speech provider unless explicitly requested in the future. ChromaDB remains the local vector database, SQLite remains the primary application database, and Docker continues to be used only as an optional sandbox for secure code execution with automatic fallback to local subprocess execution if Docker is unavailable. Legacy environment variables such as **OPENAI_API_KEY** and **OLLAMA_BASE_URL** should be treated as deprecated and ignored unless the project is intentionally migrated in the future. This substitution must be applied consistently across every AI-related module, service, backend endpoint, frontend integration, prompt template, and documentation update. Because Gemini does not always behave identically to OpenAI's function-calling or JSON mode, every prompt requiring structured output must explicitly instruct Gemini to return valid JSON, and all responses must be validated with defensive parsing and graceful error handling before being consumed by the application.
